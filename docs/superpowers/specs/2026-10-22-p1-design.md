# Session Tray P1 — Design Spec
**Date:** 2026-10-22
**Status:** Approved for planning
**Builds on:** `2026-10-18-session-tray-design.md` (v1, released as v0.2.0)
**Product doc:** `docs/product/session-tray-plan.md` §6–§8
**Visual reference:** design canvas https://claude.ai/artifact/H5v5Zr4wV4kYj35pzhno8Y (artboards: Tray popover, Window, Continue in… sheet, Stale review, Settings · Appearance, Color schemes). It is private to the owner, so the parts a builder needs are written out in §3.

---

## 1. Intent

v1 works but looks like a proof of concept: the palette is GitHub's dark theme copied verbatim, there is no type system, and rows are plain text. P1 does two things:

1. **A real visual identity.** The goal is a calm, native-macOS feel with a technical "instrument panel" layer: monospace data, small uppercase labels, hairline-divided stat cells.
2. **The P1 features** from the product plan: handoff summary, Continue in…, stale detection and archive, message peek, and rename. It also adds a first **Settings** screen, which the product plan describes (§6.5) but never scheduled.

## 2. Goals, non-goals, anti-goals

**Goals**
1. Redesign the popover and window in the **Carbon** theme (§3).
2. Handoff summary per session, built without any model (§4.1).
3. Message peek in the detail view (§4.2).
4. Continue in…: a new Claude Code session in the project folder, started with the handoff (§4.3).
5. Stale detection with a Cleanup view, and archive (§4.4).
6. Rename with an app-owned display name (§4.5).
7. Settings v1: General, Appearance, Terminal, Cleanup (§4.6).
8. Theme architecture with 5 themes and Carbon as the default (§3.4).

**Non-goals for P1**
- Codex, or any agent other than Claude Code. The Continue in… sheet shows only the targets that work.
- Deleting or moving transcript files. Archive is hide-only (§4.4).
- Syncing a rename back to Claude Code (this would mean writing to `~/.claude`).
- LLM summaries, tags, notes, git awareness, global hotkey, full-text search. These stay in P2/P3.
- The Sources and Summaries settings sections. They are on the canvas but not built in P1.

**Anti-goals (failure even if it works)**
- Any write to `~/.claude`. P1 adds no exception to the v1 rule.
- A slower popover. The handoff and peek are loaded on demand for one session, never for the whole list.
- A theme that makes status colors ambiguous. The accent must never be amber, green or purple (§3.2).

## 3. Visual design

### 3.1 Feel
- Dark, near-black graphite surfaces. Hierarchy comes from hairline borders and slight lightness steps, not shadows. The one exception is the popover and sheets, which get a soft drop shadow.
- **Geist** for UI text. **Geist Mono** for all data: paths, branches, counts, times, ids, commands, and labels.
- Labels are Geist Mono, 10.5px, uppercase, letter-spacing 0.08em, muted color (`RUNNING`, `CONTEXT`, `≈ API COST`).
- Numbers use `font-variant-numeric: tabular-nums`.
- Radii: popover and sheets 14px, cards 10px, rows 8px, buttons 6–7px, chips 4px, status chip fully rounded.
- Fonts are bundled with the app (Electron is offline-first). Both families are OFL-licensed and available on npm. Which package to use is the builder's call.

### 3.3 Components (as drawn on the canvas)
- **Session row:** dot, then title (13.5px medium, one line with ellipsis), then time or live status on the right in mono 11px. Second line in mono 11px muted: `project · branch` and `N msg`. The selected or focused row shows its actions inline: primary **Resume** (or **Open another** when running), then Copy, Peek, and a pin icon button.
  - In the popover, **Peek** opens the window with that session selected. The popover has no detail pane, no More menu, and no rename, Continue or archive. Those are window-only.
  - In the window, Peek is not shown, because the detail view already shows the peek.
- **Section header:** label on the left, count on the right, both in label style.
- **Segmented control** for the time range: an inset track with the selected segment raised.
- **Buttons:** primary (accent fill), secondary (control fill + `line-strong` border), and icon-only (`aria-label`).
- **Stat strip:** a grid of cells divided by hairlines. Each cell has a label, a mono value (20px), and a sub-line (mono 11px) or a 4px bar.
- **Command strip:** a mono `$` prompt, the exact command with ellipsis, and Copy.
- **Pulse:** the running dot has a 1.8s soft ring animation. It is disabled under `prefers-reduced-motion` and by the Settings switch.

### 3.5 Layouts
- **Popover** (top to bottom):
  - Search field with an `esc` hint.
  - A row with the time segmented control (Today / 7d / 30d / All) on the left and the project picker on the right. The Running filter chip from v1 stays, after the segmented control.
  - Sections.
  - Footer in mono 11px: "N sessions · M projects", "N stale" (when > 0), and on the right "Open window" with its shortcut.
- **Window:**
  - Toolbar: app name, search with `⌘K`/`Ctrl+K`, the week's "≈ $ this week" total, and a settings gear.
  - Below the toolbar: the list sidebar (~340px) and the detail view.
  - The detail view, top to bottom:
    1. Title with a rename pencil and the status chip (state · pid when live).
    2. A mono sub-line: path · branch · started time.
    3. Action bar: primary Resume/Open another, Continue in…, Reveal file, Pin/Unpin, and Archive pushed right.
    4. Command strip.
    5. Stat strip with 4 cells:
       - **Messages** (sub-line: "N subagents")
       - **Context** (value `118k`; if the model's context window is known, ` / 200k` and the bar, else no bar)
       - **≈ API cost** (sub-line: model)
       - **Active** (`lastActivityAt − createdAt` as `2h 41m`; sub-line: relative last activity)
    6. Two cards side by side, Handoff and Messages, stacking when narrow.
    7. A mono key/value footer: Surface, Claude Code version, File size, Title from, Session id.
- **Cleanup view:** a "Clean up" label, an "N sessions look stale" heading, the 3 rule cards in a row, the table, and a sticky footer. Archive is a second tab.
- **Settings:** a sidebar (~220px) with the section list and the app version at the bottom, plus a content column (max ~880px).
- **Continue sheet:** 760px wide. It has a header (title + one-line explanation), the target cards in a row, the folder row, the textarea taking the remaining height, and a footer with the command, Cancel and the primary button.

## 4. Features

### 4.1 Handoff summary
This is a plain-text brief of where a session stands. It is shown in the detail view and used as the first message for Continue in….

**Source, first match wins:**
1. **Compaction summary:** the text of the last `user` record with `isCompactSummary: true`. Tag: `compaction summary`.
2. **Recap:** the last `system` record with `subtype: away_summary` (already parsed as `awaySummary`). Tag: `recap`.
3. **Extract**, always built. Tag: `extracted`.

**Extract fields:**
- **Goal:** the first real user prompt (same rule as the v1 title fallback), cut to 500 characters.
- **Last ask:** the last real user prompt (`last-prompt`, else the last non-meta, non-compact user text), cut to 500 characters.
- **Files:** `file_path` inputs of assistant `tool_use` blocks named `Edit`, `Write`, `MultiEdit` and `NotebookEdit`. Paths are relative to the project when inside it, deduped, and listed most recent first. Show 3 and "+N more"; the prompt includes up to 20.
- **Branch:** the last `gitBranch`. P1 has no "commits ahead" count (that comes with git awareness in P2), so the canvas's "3 commits ahead" is not built.
- **Last answer:** the text of the last assistant `text` block, cut to 600 characters.

When the source is a compaction summary or recap, the card shows that text first. Files and Branch are still shown under it, because summaries often omit them.

**Prompt text** for Continue in… and **Copy as prompt** (template, plain text). When a summary exists (source 1 or 2), the prompt has the summary, Branch, Files touched and Last request, and leaves out Goal and Where it stopped, because the summary already covers them. With source 3, it has every extract field.
```
Continuing from session "<title>" (<first 8 chars of id>).

<summary text, if source 1 or 2>
Goal: <goal>
Branch: <branch>
Files touched:
- <path>
Last request: "<last ask>"
Where it stopped: <last answer>

Pick up from there.
```
Lines with no value are left out. Unknown values never print as "null" or "—".

**Loading:** `session:details(id)` parses that one transcript in full and returns the handoff and peek (§4.2). Nothing is added to the list payload or the index cache, except `editCount` (§4.4). Results are memoised in main by `(id, mtime, size)`.

### 4.2 Message peek
The last 6 non-meta, non-sidechain messages, oldest first:
- user text, labelled `you` (accent color)
- assistant text, labelled `claude`
- tool use, labelled `tool`, shown as one mono line: `<ToolName> <target>`. The target is `file_path`, `command` (first line) or `pattern`, whichever exists first; otherwise just the tool name.

Each text is clamped to 2 lines in the UI. The header shows "last 6 of N". **Open transcript** reveals the file (v1 `reveal` action). The full transcript reader is not in P1.

### 4.3 Continue in…
A sheet opened from the detail view's **Continue in…** button (window only).

- **Targets:**
  - **Claude Code:** a new terminal session.
  - **Clipboard only:** copies the edited prompt text, writes no file, and shows no command in the footer.
  - Codex is not shown in P1.
- **Folder:** defaults to `projectPath`. **Change** opens a native folder picker. If the project folder is missing, the user must pick one first.
- **First message:** an editable textarea filled from the prompt template (§4.1), with a rough token count (characters / 4).
- **Footer:** the exact command, then Cancel and **Open in terminal** (or **Copy** for Clipboard only).
- **Launch:** main writes the prompt to `userData/handoffs/<id>-<timestamp>.md` (app-owned) and starts an interactive `claude` in the chosen folder with the file's full contents as its first message. The terminal selection follows Settings → Terminal.
  - **What's required is the result:** the whole prompt arrives intact (quotes, newlines, `$`, backticks and non-ASCII included) in an interactive session.
  - **The mechanism is the builder's call.** The obvious first try is `claude (Get-Content -Raw -LiteralPath '<file>')` on Windows and `claude "$(cat '<file>')"` on macOS. But Windows PowerShell 5.1 mangles embedded double quotes passed to native programs, and the npm `claude.cmd` shim cuts arguments at newlines. Likely fixes are escaping for 5.1, preferring `pwsh` when present, or resolving the real `claude` executable.
  - Supported installs: the native installer and the npm global install.
  - Cover both in the invocation tests, plus one manual launch per platform with a prompt containing quotes and newlines.
- Handoff files older than 7 days are deleted on app start. They live in userData, so this does not touch `~/.claude`.
- The old session is not changed. Claude Code may write its own `continued-in` link; the app does not.

### 4.4 Stale detection and archive
**Rules** (all on by default, thresholds editable in Settings → Cleanup):
1. No activity for N days (default 30).
2. Trivial: fewer than N messages (default 3) **and** `editCount === 0`.
3. Project folder is gone (`projectExists === false`).

Pinned sessions, running sessions and archived sessions are never flagged. `editCount` is the number of `Edit`/`Write`/`MultiEdit`/`NotebookEdit` tool uses. The parser adds it to `TranscriptMeta`, which bumps the index cache to `index-v2.json`. The old file is ignored, which costs one cold scan.

**Archive is hide-only.** Archived ids live in `app-state.json`. Archived sessions are left out of every section and out of the count, and transcripts are never touched. Running sessions cannot be archived. If an archived session becomes live again, it is shown in Running anyway (live beats archive).

**Surfaces:**
- **Popover footer:** "N stale" when N > 0. Clicking it opens the window on the Cleanup view.
- **Cleanup view** (window): rule cards with checkboxes and counts. Below them, a table with checkbox, title, project, a "why" tag (`idle 34d`, `trivial`, `folder gone`), last active, message count and size. All rows start checked except pinned ones (pinned are never listed anyway). The footer shows "N selected · size", **Keep all** and **Archive N**.
  - **Keep all** marks the current stale set as reviewed, stored as `keptAt: Record<id, timestamp>`.
  - A kept session is not flagged again until it has new activity after `keptAt` or 30 days have passed since `keptAt`, whichever comes first. The reasons are not stored.
- Stale sessions stay listed in Recent as normal. The plan's "hide stale behind a toggle" is not in P1; the footer count and the Cleanup view are the way in.
- **Archive tab** in the Cleanup view: archived sessions with **Restore**. No countdown, because nothing is deleted.
- Detail view **Archive** button: archives one session.

### 4.5 Rename
- The pencil next to the detail title starts inline editing. Enter saves, Esc cancels, and an empty value clears the rename.
- Names are stored as `names: Record<id, string>` in `app-state.json`.
- The display title is the app name first, then the v1 chain (custom → agent → ai → prompt). `titleSource` gains `'app'`.
- Search matches the app name.
- No sync to Claude Code. The user can still `/rename` inside Claude, and that becomes `custom` as in v1.

### 4.6 Settings v1
Opened from the tray right-click menu ("Settings…"), a gear in the window toolbar, and `⌘,` / `Ctrl+,` in the window. It is a window view with a sidebar. P1 sections:

- **General:** Launch at login (Electron login item).
- **Appearance:**
  - Theme picker: 5 preview cards, Carbon tagged `default`.
  - Follow system appearance: off by default. When on, Paper is used while the OS is light, and the chosen theme while dark. If the chosen theme is Paper itself, the switch does nothing.
  - Row density: Comfortable / Compact.
  - Pulse running sessions: on by default.
- **Terminal:** where Resume and Continue open sessions. Windows: Windows Terminal (when found) / PowerShell. macOS: Terminal. The row shows the exact command that will run.
- **Cleanup:** the three rules with on/off and thresholds.

Settings live in `app-state.json` under `settings`. Changes apply immediately, with no Save button.

## 5. Data changes

**`TranscriptMeta`:** add `editCount: number`. `titleSource` gains `'app'` on `SessionRecord` only. Cache file becomes `index-v2.json`.

**`app-state.json`** (all fields optional on read; unknown or invalid fields fall back to defaults, never throw):
```ts
interface AppState {
  pins: string[]
  names: Record<string, string>
  archived: string[]
  keptAt: Record<string, number>
  settings: {
    theme: 'carbon' | 'graphite' | 'midnight' | 'ink' | 'paper'
    followSystem: boolean
    density: 'comfortable' | 'compact'
    pulse: boolean
    terminal: 'auto' | 'wt' | 'powershell' | 'terminal'
    launchAtLogin: boolean
    stale: { idleDays: number | null; trivialMessages: number | null; missingFolder: boolean }
  }
}
```
A rule set to `null` is off. Writes stay atomic (tmp + rename), as in v1.

**New detail type:**
```ts
interface SessionDetails {
  handoff: {
    source: 'compact' | 'recap' | 'extract'
    summary: string | null
    goal: string | null
    lastAsk: string | null
    files: string[]
    branch: string | null
    lastAnswer: string | null
  }
  peek: Array<{ role: 'user' | 'assistant' | 'tool'; text: string; ts: number | null }>
  messageTotal: number
}
```

**IPC additions:**
- `session:details(id)` returns `SessionDetails | null`
- `session:continue(id, { folder, prompt, target })`
- `session:rename(id, name | null)`
- `session:archive(ids)` / `session:restore(ids)` / `session:keep(ids)`
- `settings:set(patch)`
- `app:openSettings`
- `dialog:pickFolder`

`SessionsPayload` gains the app-state fields the client needs: `names`, `archived`, `keptAt` and `settings`. Ids are validated as in v1 before any spawn or state write.

## 6. Testing
- **Fixtures** (new, under `desktop/src/core/__tests__/fixtures/`):
  - a transcript with a compaction summary
  - one with Edit/Write/MultiEdit tool uses (files and `editCount`)
  - a 2-message trivial session
  - one with malformed tool_use blocks (fail-soft)
- **desktop (Jest):** handoff extraction, source priority, prompt template (missing fields dropped), peek shaping, stale rules (each rule, exemptions, `keptAt`), app-state load/migrate from the v1 `{pins}` shape, and continue invocation per platform (quoting of folder and file paths with spaces, `'`, `$` and backticks).
- **client (Vitest):** archived and renamed records in `buildSections`, the stale count, rename editing in the detail view, the Continue sheet's prompt editing, and the theme attribute applied from settings.
- Manual check of Carbon on Windows and macOS before release.

## 7. Suggested order
1. Theme tokens + Carbon restyle of the existing popover, rows and detail, with bundled fonts. → verify: the screens match the canvas, and the existing tests still pass.
2. App-state v2 + Settings window (General, Appearance with Carbon only, Terminal). → verify: settings persist across restart, and a v1 `app-state.json` loads.
3. Parser: `editCount` and the `index-v2` cache, then `session:details` with handoff + peek. → verify: fixture tests.
4. Detail view: stat strip, handoff card, peek, rename. → verify: client tests and a manual pass.
5. Continue in… sheet + launch. → verify: invocation tests; a manual launch on Windows.
6. Stale rules, Cleanup view, archive/restore/keep, popover footer. → verify: rule tests; archive survives restart.
7. The remaining 4 themes + Follow system. → verify: contrast check per theme.

## 8. Left to the builder
- Exact component structure, state handling in the client, and the IPC naming within the pattern above.
- How fonts are packaged.
- Paper's full token set and fine tuning of non-Carbon status colors, within the §3.2 rules.
- Popover height and window minimum sizes, as long as the popover still fits small screens (v1 #7 fix).
- The keyboard shortcuts beyond `⌘,`/`Ctrl+,` and Esc.

## 9. Decisions made during design (for review)
- **Archive is hide-only.** This keeps the read-only rule on `~/.claude` and drops the product plan's "move files with undo" and removal countdown.
- **Rename is app-only** and is never synced to Claude Code.
- **Handoff and peek load on demand** per session and are not cached in the index.
- **Codex is hidden** in Continue in… until the Codex adapter exists.
- **Settings joins P1**, limited to General, Appearance, Terminal and Cleanup.
- **"Keep all"** in Cleanup suppresses the current stale set (until new activity or 30 days) rather than adding a permanent "never stale" flag.
- **The popover hands off to the window** for peek, rename, Continue in… and archive.
- **Stale sessions stay visible** in Recent.
- **The Continue launch mechanism is flexible.** The result is the requirement (§4.3).
- **"Clipboard only"** copies the prompt text, not a command.
