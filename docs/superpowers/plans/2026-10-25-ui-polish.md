# UI Polish Pass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Session details with the summary first and the rest in tabs, one copy control, and no native browser controls anywhere in the client.

**Architecture:** Renderer-only. New primitives live in `client/src/components/ui/` (Radix-based, restyled with the theme tokens from `lib/themes.ts`). `DetailPanel` is split into header, summary and tabs pieces; FilterBar, Settings and Cleanup swap their native controls for the primitives. No IPC, `core/` or `SessionRecord` changes.

**Tech Stack:** React 18, Tailwind CSS v3, Radix UI primitives (via shadcn recipes), Vitest + Testing Library (+ user-event).

**Spec:** `docs/superpowers/specs/2026-10-25-ui-polish-design.md`. Final mockup: `.superpowers/brainstorm/522-1792920283/content/details-layout-v6.html`.

## Global Constraints

- Colors only from theme tokens (`bg-canvas`, `bg-surface`, `bg-control`, `text-text`, `text-text-2`, `text-muted`, `text-faint`, `border-line`, `border-line-strong`, `bg-accent`, `text-on-accent`, state colors). No hex in components. All five themes must work.
- Fonts: Geist Sans for UI text; Geist Mono only for machine text (ids, commands, paths, branches, numbers, times).
- Labels are sentence case, sans, `text-muted`. No `uppercase`/`tracking-[.08em]` label styling in `client/src/components` or `client/src/views`.
- Copy appears only on: session id, resume command, summary (as prompt), project path, each PR link, and the session row's action strip.
- Tooltips: Radix, side `top`, rendered in a portal. Copy tooltip reads "Copy" (or a specific label), then "Copied" for 1.5 s.
- No `type="number"`, `<select` or `type="checkbox"` left in `client/src`.
- Dependencies: `@radix-ui/react-select`, `@radix-ui/react-checkbox`, `@radix-ui/react-tooltip`, `@radix-ui/react-tabs`, `@radix-ui/react-dropdown-menu`; dev: `@testing-library/user-event`. Nothing else unless a recipe genuinely needs it.
- Motion only as action feedback; `prefers-reduced-motion` disables transitions.
- `npm test -w client` and `npm test -w desktop` pass after every task.

## Review Focus

1. **Very long values** (300-char title, deep Windows path, full resume command): they truncate on one line with the full text in a tooltip or `title`; the details pane never scrolls sideways. → Task 4 test.
2. **Remembered tab missing for the next session** (Pull requests selected, next session has no PRs): Messages is selected, not an empty panel. → Task 5 test.
3. **Copy clicked, then the component unmounts within 1.5 s** (switch session right after copying): no React state-update warning, no stuck "Copied" on the next session. → Task 1 test.
4. **Stepper edge input** (typing `abc`, `0`, `-5`, pressing − at 1, + from Off): `abc`/`0`/`-5` → Off (`null`); − at 1 → Off; + from Off → 1. → Task 2 test.
5. **Selects in the small popover window** (project list opened near the bottom, long project names): the menu stays inside the window and long names truncate. → Task 2 (Radix `position="popper"`, `collisionPadding={8}`, `max-h` + scroll on content; test that options render and long names carry `truncate`).
