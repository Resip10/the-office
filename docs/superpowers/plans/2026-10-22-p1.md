# Session Tray P1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle Session Tray in the Carbon theme and add the P1 features: handoff summary, message peek, rename, Continue in…, stale detection with Cleanup and archive, Settings, and themes.

**Architecture:**
- **Pure logic goes in `desktop/src/core/`**, unit-tested with fixtures and no Electron. That covers app-state v2, details/handoff, stale rules, and the continue invocation.
- **`main.ts` wires IPC**, and `preload.ts` exposes it as `window.sessionTray`.
- **The client reads theme tokens from CSS variables** that `client/src/lib/themes.ts` sets on `<html>`. Tailwind color names point at those variables.

**Tech Stack:** Electron, TypeScript, React 18, Vite, Tailwind CSS v3, Jest + ts-jest (desktop), Vitest + Testing Library (client).

**Spec:** `docs/superpowers/specs/2026-10-22-p1-design.md`. Read it first. Section numbers (§) below refer to it.

**Branch:** `feature/p1`. One commit per task. One PR at the end.

## Global Constraints

- **Never write to `~/.claude`.** App data lives only in `app.getPath('userData')`: `index-v2.json`, `app-state.json`, `handoffs/`.
- **Session ids** are validated against `/^[0-9a-f-]{36}$/` before any spawn or state write.
- **`core/` never throws on bad input.** Unknown values render as `—` in the UI and never as `null` in prompt text.
- **The accent is never amber, green or purple.** Status colors keep their meaning: running `#FFB340`, idle `#32D74B`, other live `#BF8CFF`, ended `#636369` (Carbon).
- **Type:** Geist for UI, Geist Mono for data and labels. Labels are 10.5px uppercase with `letter-spacing: .08em`. Numbers use `tabular-nums`. Fonts are bundled, never loaded from the network.
- **The pulse is disabled** under `prefers-reduced-motion` and when `settings.pulse === false`.
- **Popover vs window:** the popover hands off to the window for peek, rename, Continue in… and archive.
- **Before every commit:** `npm test -w desktop` and `npm test -w client` both pass.

## Review Focus

1. **A Continue prompt with `"`, `'`, `$`, backticks, newlines and non-ASCII**, on Windows PowerShell 5.1 and with the npm `claude.cmd` shim. Expected: the full prompt arrives as one first message. *(Task 9 tests.)*
2. **A corrupt, partial or v1-shaped `app-state.json`.** Expected: it loads with defaults, existing pins are kept, and nothing throws. *(Task 3 tests.)*
3. **A transcript deleted or unreadable between list and detail.** Expected: `session:details` returns `null`, and the detail view shows the stat strip and command but no handoff/peek cards. No crash. *(Tasks 6 and 7 tests.)*
4. **An archived session becomes live again.** Expected: it shows in Running. *(Task 11 test.)*
5. **A rename to whitespace only, or to 500 characters.** Expected: whitespace clears the rename; long names are trimmed to 200 characters on save. *(Task 8 test.)*
